Technical report

One page: what we built, how well it works on our own labels of the sample videos, what worked, what did not, and what we would do next.

What we built

A single command (python run_submission.py --videos DIR --out predictions.json) runs two independent chains per video. Part A detects road users with a COCO-pretrained YOLO11, tracks them, and applies one rule module per family of event classes to the trajectories, read against a model of the fixed camera (carriageway, lane directions, stop lines, crossings) that was learned without labels from the sample videos. Part B runs its own detector-plus-tracker strictly causally and turns time-to-collision, hard braking, wrong-way motion and contact into a calibrated risk score. Details on the approach page.

What worked

  • Learning the road layout from trajectories. A per-cell lane-direction histogram (one vote per vehicle) gives a clean definition of "against the traffic" without drawing a single lane. Rasterising each trajectory between analysed frames was essential: fast cars otherwise leave holes in the map.
  • Measuring kinematics in object sizes. Speeds and gaps divided by the object's own size behave the same near and far from the camera, so one threshold works across the frame.
  • A precision-first stance. The macro F1 averages classes in the test set or in our predictions, so a class we predict wrongly costs as much as a class we miss. Every rule requires sustained evidence.
  • Test-driven rules. Each rule has a synthetic-trajectory test with the expected start and end; the tests caught a tracker bug (fast new tracks restarted every frame) and the map-hole bug before any real video was used.

What did not work (yet)

  • Boundaries at IoU 0.7. Our start and end times inherit the analysis rate and smoothing (±0.2 s) and, for signal events, the uncertainty of when a phase changes. The 0.7 threshold is where we lose most.
  • Small, far objects. Boxes a few dozen pixels wide jitter by a large fraction of their size, which reads as violent acceleration; we exclude them from accident and near-miss analysis, so events far from the camera are missed.
  • Signal state without seeing the lights. When the signal heads are not visible, a red phase is only known while a queue waits at the line; a red-light runner on an empty approach is invisible to us.
  • Fire, smoke and obstacles rely on colour and background differences and are kept deliberately strict; on the samples they are more likely to miss than to fire.

What we would do next

  • Fine-tune a short-clip video classifier (for example on DoTA and CCD crashes) to re-score accident and near-miss candidates, which rules alone rank poorly.
  • Refine boundaries with a second, full-frame-rate pass around each candidate.
  • A homography from the lane markings to metres, so speeds, gaps and time-to-collision are physical.
  • More dev labels: four sample videos give only a handful of events per class.
